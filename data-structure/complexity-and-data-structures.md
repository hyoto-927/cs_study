## 시간 복잡도와 공간 복잡도

<a name="q1"></a>
### Q1. 시간 복잡도와 공간 복잡도의 차이는 무엇인가요?

> "시간 복잡도는 입력 크기가 증가할 때 알고리즘의 연산량이 얼마나 증가하는지를 나타내고, 공간 복잡도는 입력 크기가 증가할 때 필요한 메모리 사용량이 얼마나 증가하는지를 나타냅니다.
>
> 알고리즘을 선택할 때는 실행 속도뿐 아니라 메모리 사용량도 함께 고려해야 합니다."

**핵심 요약**

**시간 복잡도 = 연산량의 증가율 / 공간 복잡도 = 메모리 사용량의 증가율**

<a name="q1-1"></a>
#### ↳ Q1-1. 시간 복잡도를 줄이면 공간 복잡도도 줄어드나요?

> "반드시 그렇지는 않습니다.
>
> 예를 들어 이미 계산한 결과를 메모리에 저장하는 메모이제이션은 추가 메모리를 사용하는 대신 같은 계산을 반복하지 않아 실행 시간을 줄입니다.
>
> 이처럼 시간과 공간 사이에는 트레이드오프가 발생할 수 있습니다."

**핵심 요약**

**시간을 줄이기 위해 메모리를 더 사용할 수도 있다.**

---

<a name="q1-2"></a>
#### ↳ Q1-2. 시간 복잡도에서 왜 실제 실행 시간이 아니라 증가율을 보나요?

> "실제 실행 시간은 CPU 성능, 프로그래밍 언어, 실행 환경 등에 따라 달라질 수 있기 때문입니다.
>
> 복잡도는 이런 환경 차이보다 입력 크기가 커졌을 때 연산량이 어떻게 증가하는지를 비교하기 위해 사용합니다."

**핵심 요약**

**복잡도는 컴퓨터 성능이 아니라 입력 증가에 따른 연산량 증가를 비교한다.**

---

<a name="q2"></a>
### Q2. Big-O, Big-Ω, Big-Θ의 차이는 무엇인가요?

> "Big-O는 알고리즘의 증가율에 대한 상한을, Big-Ω는 하한을, Big-Θ는 상한과 하한이 모두 같은 증가율을 나타낼 때 사용합니다.
>
> 알고리즘 분석에서는 일반적으로 성능의 상한을 표현하기 위해 Big-O 표기법을 가장 많이 사용합니다."

**핵심 요약**

**O = 상한 / Ω = 하한 / Θ = 정확한 증가 차수**

<a name="q2-1"></a>
#### ↳ Q2-1. Big-O는 무조건 최악의 시간 복잡도를 의미하나요?

> "정확히는 아닙니다.
>
> Big-O 자체는 증가율의 상한을 나타내는 표기법이고, 알고리즘을 설명할 때 최악의 경우를 Big-O로 표현하는 경우가 많아서 흔히 최악 시간 복잡도와 함께 사용됩니다."

**핵심 요약**

**Big-O는 상한 표기이고, 최악의 경우를 표현하는 데 자주 사용된다.**

---

<a name="q3"></a>
### Q3. 시간 복잡도를 계산할 때 상수항과 낮은 차수를 생략하는 이유는 무엇인가요?

> "입력 크기가 매우 커질수록 가장 높은 차수의 항이 전체 증가율을 지배하기 때문입니다.
>
> 예를 들어 `3N² + 5N + 10`에서 N이 커질수록 N²의 영향이 가장 커지므로 `O(N²)`으로 표현합니다."

**핵심 요약**

**입력이 커지면 가장 빠르게 증가하는 항이 성능을 지배한다.**

---

<a name="q4"></a>
### Q4. 반복문이 두 개 있으면 항상 O(N²)인가요?

> "아닙니다.
>
> 두 반복문이 서로 중첩되어 각각 N번 실행된다면 보통 O(N²)이지만, 두 반복문이 순차적으로 각각 N번 실행된다면 `N + N`이므로 O(N)입니다."

예를 들어:

```
for (int i = 0; i < N; i++) {
}

for (int i = 0; i < N; i++) {
}
```

이건:

```
N + N = 2N
→ O(N)
```

입니다.

반면:

```
for (int i = 0; i < N; i++) {
    for (int j = 0; j < N; j++) {
    }
}
```

는:

```
N × N
→ O(N²)
```

입니다.

**핵심 요약**

**반복문의 개수가 아니라 실제 실행 횟수를 기준으로 복잡도를 계산한다.**

---

<a name="q5"></a>
### Q5. 공간 복잡도 O(1)과 O(N)의 차이는 무엇인가요?

> "O(1)은 입력 크기가 증가해도 추가로 사용하는 메모리 크기가 거의 일정한 경우이고, O(N)은 입력 크기에 비례하여 사용하는 메모리가 증가하는 경우입니다."

**핵심 요약**

**O(1)은 고정 메모리 / O(N)은 입력 크기만큼 메모리 증가**

<a name="section-02"></a>
## 배열과 리스트

<a name="q6"></a>
### Q6. Array와 ArrayList의 차이는 무엇인가요?

> "Array는 생성할 때 크기가 고정되는 배열이고, ArrayList는 내부적으로 배열을 사용하지만 필요한 경우 더 큰 배열을 만들어 크기를 확장하는 동적 배열입니다.
>
> Array는 기본형과 객체를 모두 저장할 수 있지만 ArrayList는 제네릭을 사용할 경우 객체 타입을 저장합니다."

**핵심 요약**

**Array = 고정 크기 배열 / ArrayList = 크기가 자동으로 확장되는 동적 배열**

<a name="q6-1"></a>
#### ↳ Q6-1. ArrayList도 결국 배열인데 어떻게 크기가 늘어나나요?

> "현재 내부 배열의 용량이 부족하면 더 큰 배열을 새로 생성하고 기존 요소를 새 배열로 복사한 뒤 새로운 배열을 사용합니다."

**핵심 요약**

**ArrayList는 용량이 부족하면 더 큰 배열을 만들어 기존 데이터를 복사한다.**

---

<a name="q7"></a>
### Q7. ArrayList와 LinkedList 중 어떤 것을 선택하겠습니까?

> "조회와 순회가 많다면 일반적으로 ArrayList를 선택하겠습니다.
>
> ArrayList는 인덱스로 O(1)에 접근할 수 있고 연속적인 배열 구조라 캐시 효율도 좋습니다.
>
> LinkedList는 노드 위치를 이미 알고 있는 상황에서 연결 정보만 변경하면 삽입·삭제할 수 있으므로 그런 작업이 필요한 특수한 상황에서 고려할 수 있습니다."

**핵심 요약**

**조회·순회가 많으면 ArrayList, 노드 위치가 이미 알려진 잦은 연결 변경에는 LinkedList를 고려한다.**

<a name="q7-1"></a>
#### ↳ Q7-1. LinkedList는 삽입과 삭제가 O(1)인데 왜 항상 유리하지 않나요?

> "삽입하거나 삭제할 노드의 위치를 먼저 찾아야 한다면 탐색에 O(N)이 필요하기 때문입니다.
>
> 또한 각 노드가 이전·다음 노드의 참조를 별도로 저장하고 메모리에 분산되어 있어 ArrayList보다 메모리와 캐시 효율 측면에서 불리할 수 있습니다."

**핵심 요약**

**LinkedList는 위치를 찾는 데 O(N)이 필요할 수 있어서 삽입·삭제가 항상 O(1)은 아니다.**

---

<a name="q7-2"></a>
#### ↳ Q7-2. ArrayList는 왜 조회가 O(1)인가요?

> "내부 배열의 시작 위치와 인덱스를 이용해 원하는 요소의 메모리 위치를 바로 계산할 수 있기 때문입니다."

**핵심 요약**

**ArrayList는 인덱스로 위치를 바로 계산할 수 있어 조회가 O(1)이다.**

---

<a name="q8"></a>
### Q8. ArrayList는 조회가 빠르지만 중간 삽입과 삭제는 느린 이유가 무엇인가요?

> "ArrayList는 배열 기반이므로 인덱스로 요소에 바로 접근할 수 있어 조회는 O(1)입니다.
>
> 하지만 중간에 요소를 삽입하거나 삭제하면 뒤에 있는 요소들을 한 칸씩 이동해야 하므로 O(N)이 필요할 수 있습니다."

**핵심 요약**

**ArrayList는 인덱스 조회는 빠르지만 중간 삽입·삭제는 요소 이동 때문에 O(N)이다.**

---

<a name="q9"></a>
### Q9. ArrayList의 끝에 데이터를 추가하는 것이 O(1)이라고 하는 이유는 무엇인가요?

> "내부 배열에 여유 공간이 있다면 마지막 위치에 데이터를 바로 저장할 수 있기 때문에 O(1)입니다.
>
> 다만 용량이 부족하면 더 큰 배열을 만들고 기존 데이터를 복사해야 하므로 그 한 번의 연산은 O(N)이 될 수 있습니다.
>
> 하지만 배열 확장은 매번 발생하지 않기 때문에 여러 번의 추가 연산을 전체적으로 나누어 보면 맨 뒤 추가는 분할 상환 O(1)입니다."

**핵심 요약**

**ArrayList의 맨 뒤 추가는 가끔 O(N) 확장이 있지만 전체적으로는 분할 상환 O(1)이다.**

<a name="q9-1"></a>
#### ↳ Q9-1. 분할 상환 시간 복잡도란 무엇인가요?

> "일부 연산에서 큰 비용이 발생하더라도 여러 연산에 걸친 총비용을 나누어 연산 하나당 비용을 분석하는 방식입니다.
>
> 일반적인 입력 분포를 가정하는 평균 시간 복잡도와는 다른 개념입니다."

**핵심 요약**

**분할 상환 복잡도는 가끔 발생하는 큰 비용을 여러 연산에 나누어 계산한다.**

---

<a name="section-03"></a>
## Hash 기반 자료구조

<a name="q10"></a>
### Q10. HashMap과 HashSet의 차이는 무엇인가요?

> "HashMap은 Key와 Value의 쌍을 저장하는 Map이고, HashSet은 중복되지 않는 값 자체를 저장하는 Set입니다.
>
> Java의 HashSet은 내부적으로 HashMap을 사용하며 저장할 값을 HashMap의 Key로 관리합니다."

**핵심 요약**

**HashMap = Key-Value / HashSet = 중복 없는 값**

---

<a name="q11"></a>
### Q11. HashSet은 중복을 어떻게 방지하나요?

> "HashSet은 요소의 `hashCode()`를 이용해 저장할 위치를 찾고, 같은 위치에 후보가 있으면 `equals()`를 이용해 실제로 같은 객체인지 확인합니다.
>
> 이미 동일한 요소가 존재하면 새로 추가하지 않아 중복을 방지합니다."

**핵심 요약**

**HashSet은 hashCode()로 위치를 찾고 equals()로 동일성을 확인해 중복을 막는다.**

<a name="q11-1"></a>
#### ↳ Q11-1. hashCode()가 같으면 무조건 같은 객체인가요?

> "아닙니다.
>
> 서로 다른 객체도 같은 hashCode를 가질 수 있습니다. 따라서 hashCode가 같더라도 equals()를 이용해 실제 동등성을 추가로 확인해야 합니다."

**핵심 요약**

**같은 hashCode라고 같은 객체는 아니므로 equals() 확인이 필요하다.**

---

<a name="q12"></a>
### Q12. HashMap에서 해시 충돌이란 무엇인가요?

> "서로 다른 Key가 해시 계산 결과 같은 버킷에 배정되는 현상을 해시 충돌이라고 합니다.
>
> 충돌이 발생하면 같은 버킷 내부에서 Key를 추가로 비교하여 원하는 데이터를 찾아야 하므로 충돌이 많아질수록 성능이 저하될 수 있습니다."

**핵심 요약**

**해시 충돌은 서로 다른 Key가 같은 버킷에 배정되는 현상이다.**

<a name="q12-1"></a>
#### ↳ Q12-1. 해시 충돌이 발생하면 데이터를 잃어버리나요?

> "아닙니다.
>
> HashMap은 같은 버킷 안에서 여러 엔트리를 관리하면서 실제 Key를 비교해 데이터를 구분합니다."

**핵심 요약**

**충돌은 같은 위치를 공유한다는 뜻이지 기존 데이터가 사라진다는 뜻은 아니다.**

---

<a name="q13"></a>
### Q13. HashMap은 왜 평균 O(1)에 조회할 수 있나요?

> "Key의 hashCode를 이용해 데이터가 들어 있을 버킷의 위치를 계산할 수 있으므로 처음부터 모든 데이터를 순차적으로 탐색할 필요가 없기 때문입니다.
>
> 다만 해시 충돌이 많아지면 추가 탐색이 필요해 성능이 떨어질 수 있습니다."

**핵심 요약**

**HashMap은 해시를 이용해 데이터를 찾을 위치를 바로 좁힐 수 있어 평균 O(1)이다.**

---

<a name="q14"></a>
### Q14. HashMap, LinkedHashMap, TreeMap의 차이는 무엇인가요?

> "HashMap은 빠른 Key 기반 조회를 제공하지만 순서를 보장하지 않습니다.
>
> LinkedHashMap은 연결 정보를 추가로 관리하여 일반적으로 삽입 순서나 설정에 따라 접근 순서를 유지할 수 있습니다.
>
> TreeMap은 Red-Black Tree를 기반으로 Key를 정렬된 상태로 유지합니다."

**핵심 요약**

**HashMap = 빠른 조회 / LinkedHashMap = 순서 유지 / TreeMap = Key 정렬**

---

<a name="q15"></a>
### Q15. HashMap과 TreeMap은 어떤 상황에서 사용하나요?

> "빠른 Key 기반 조회가 가장 중요하다면 HashMap을 사용하고, Key의 정렬된 순서나 범위 검색이 필요하다면 TreeMap을 사용합니다.
>
> HashMap의 조회·삽입·삭제는 평균 O(1)이고, TreeMap은 O(log N)입니다."

**핵심 요약**

**속도가 중요하면 HashMap, 정렬·범위 검색이 필요하면 TreeMap**

<a name="q15-1"></a>
#### ↳ Q15-1. TreeMap은 왜 O(log N)을 유지하나요?

> "TreeMap은 Red-Black Tree라는 자가 균형 이진 탐색 트리를 사용합니다.
>
> 삽입과 삭제 후에도 트리가 한쪽으로 지나치게 치우치지 않도록 균형을 조정하여 트리 높이를 O(log N) 수준으로 유지하기 때문입니다."

**핵심 요약**

**TreeMap은 균형 트리를 사용해 높이를 O(log N)으로 유지한다.**

---

<a name="section-04"></a>
## Set 자료구조

<a name="q16"></a>
### Q16. HashSet과 TreeSet은 언제 사용하나요?

> "중복을 제거하면서 빠른 조회와 삽입이 중요하다면 HashSet을 사용하고, 중복 제거와 함께 값의 정렬된 순서가 필요하다면 TreeSet을 사용합니다.
>
> HashSet은 평균 O(1), TreeSet은 일반적으로 O(log N)의 탐색·삽입·삭제 성능을 가집니다."

**핵심 요약**

**HashSet = 빠른 중복 제거 / TreeSet = 정렬된 중복 제거**

<a name="q16-1"></a>
#### ↳ Q16-1. Set과 List의 가장 큰 차이는 무엇인가요?

> "List는 중복을 허용하고 순서를 가지는 자료구조이고, Set은 같은 요소의 중복 저장을 허용하지 않는 자료구조입니다."

**핵심 요약**

**List는 중복 O / Set은 중복 X**

---

<a name="section-05"></a>
## Stack과 Queue

<a name="q17"></a>
### Q17. Stack 대신 ArrayDeque 사용을 권장하는 이유는 무엇인가요?

> "Java의 Stack은 Vector를 상속한 오래된 클래스이고 주요 연산이 동기화되어 있어 일반적인 단일 스레드 환경에서는 불필요한 비용이 발생할 수 있습니다.
>
> ArrayDeque은 양쪽 끝에서 데이터를 효율적으로 추가하고 제거할 수 있어 일반적인 Stack이나 Queue 구현에 적합합니다."

**핵심 요약**

**Java에서는 일반적인 Stack·Queue 구현에 Stack보다 ArrayDeque을 권장한다.**

<a name="q17-1"></a>
#### ↳ Q17-1. Stack과 Queue의 차이는 무엇인가요?

> "Stack은 마지막에 들어온 데이터가 먼저 나오는 LIFO 구조이고, Queue는 먼저 들어온 데이터가 먼저 나오는 FIFO 구조입니다."

**핵심 요약**

**Stack = LIFO / Queue = FIFO**

---

<a name="q17-2"></a>
#### ↳ Q17-2. ArrayDeque는 왜 Stack과 Queue 둘 다 구현할 수 있나요?

> "Deque는 Double Ended Queue의 약자로 양쪽 끝에서 데이터를 추가하고 제거할 수 있기 때문입니다.
>
> 한쪽 끝만 이용하면 Stack처럼 사용할 수 있고, 한쪽에서 넣고 반대쪽에서 빼면 Queue처럼 사용할 수 있습니다."

**핵심 요약**

**Deque는 양쪽 끝을 사용할 수 있어 Stack과 Queue 역할을 모두 할 수 있다.**

---

<a name="section-06"></a>
## 정렬 알고리즘

<a name="q18"></a>
### Q18. 퀵 정렬과 병합 정렬의 차이는 무엇인가요?

> "퀵 정렬은 피벗을 기준으로 데이터를 분할하여 정렬하는 방식으로 평균 O(N log N)이지만 분할이 매우 불균형하면 최악 O(N²)이 될 수 있습니다.
>
> 병합 정렬은 데이터를 절반씩 나눈 뒤 정렬된 결과를 병합하며 최악의 경우에도 O(N log N)을 보장하지만 일반적인 배열 구현에서는 O(N)의 추가 메모리가 필요합니다."

**핵심 요약**

**Quick Sort = 평균 빠르지만 최악 O(N²) / Merge Sort = O(N log N) 보장, 추가 메모리 필요**

<a name="q18-1"></a>
#### ↳ Q18-1. 안정 정렬이란 무엇인가요?

> "동일한 정렬 Key를 가진 요소들의 기존 상대적 순서가 정렬 후에도 유지되는 정렬 방식입니다."

예:

```
정렬 전
A(90), B(80), C(90)

점수 내림차순 정렬

안정 정렬
A(90), C(90), B(80)
```

A와 C의 점수가 같을 때 기존의 A → C 순서를 유지합니다.

**핵심 요약**

**안정 정렬은 같은 Key를 가진 요소의 기존 순서를 유지한다.**

---

<a name="q18-2"></a>
#### ↳ Q18-2. 병합 정렬은 왜 O(N)의 추가 공간이 필요한가요?

> "분할된 두 배열을 정렬된 순서로 합칠 때 결과를 임시로 저장할 공간이 필요하기 때문입니다."

**핵심 요약**

**병합 과정에서 임시 배열이 필요하기 때문에 추가 메모리를 사용한다.**

---

<a name="section-07"></a>
## 추가로 준비하면 좋은 질문

여기부터는 **제가 추가로 추천하는 질문**이라  표시를 하지 않았습니다.

---

<a name="q19"></a>
### Q19. 시간 복잡도가 O(log N)이라는 것은 어떤 의미인가요?

> "입력 크기가 증가하더라도 매 단계마다 탐색 범위를 일정 비율로 줄여 연산 횟수가 천천히 증가하는 것을 의미합니다.
>
> 대표적으로 이진 탐색이 O(log N)입니다."

**핵심 요약**

**O(log N)은 매 단계 탐색 범위를 크게 줄이는 알고리즘에서 자주 나타난다.**

<a name="q19-1"></a>
#### ↳ Q19-1. 왜 이진 탐색은 O(log N)인가요?

> "한 번 비교할 때마다 탐색 범위를 절반으로 줄이기 때문입니다.
>
> N → N/2 → N/4 → N/8처럼 줄어들어 약 log₂N번이면 탐색이 끝납니다."

**핵심 요약**

**이진 탐색은 매번 범위를 절반으로 줄여 O(log N)이다.**

---

<a name="q20"></a>
### Q20. O(N log N)은 주로 어디에서 나타나나요?

> "데이터를 log N 단계로 나누고 각 단계에서 전체 N개의 데이터를 처리하는 알고리즘에서 주로 나타납니다.
>
> 대표적으로 병합 정렬과 평균적인 퀵 정렬이 있습니다."

**핵심 요약**

**N개의 데이터를 log N 단계로 처리하면 O(N log N)이 나타난다.**

---

<a name="q21"></a>
### Q21. 배열에서 중간 삽입이 O(N)인 이유는 무엇인가요?

> "중간에 새로운 공간을 만들기 위해 삽입 위치 이후의 요소들을 한 칸씩 뒤로 이동시켜야 하기 때문입니다."

**핵심 요약**

**배열 중간 삽입은 뒤 요소들을 이동해야 해서 O(N)이다.**

---

<a name="q22"></a>
### Q22. HashMap의 Key로 객체를 사용할 때 무엇을 주의해야 하나요?

> "`equals()`와 `hashCode()`의 규칙을 올바르게 구현해야 합니다.
>
> equals()가 true인 두 객체는 같은 hashCode를 반환해야 HashMap이나 HashSet에서 동일한 Key 또는 요소로 올바르게 처리할 수 있습니다."

**핵심 요약**

**Hash 기반 자료구조에서는 equals()와 hashCode() 규칙이 중요하다.**

<a name="q22-1"></a>
#### ↳ Q22-1. equals()는 같은데 hashCode()가 다르면 어떤 문제가 생기나요?

> "논리적으로 같은 객체인데 서로 다른 버킷에서 관리될 수 있어 HashMap이나 HashSet이 같은 객체를 제대로 찾거나 중복 판단하지 못할 수 있습니다."

**핵심 요약**

**equals가 같은 객체는 반드시 같은 hashCode를 가져야 한다.**

---

<a name="q23"></a>
### Q23. HashMap의 Load Factor란 무엇인가요?

> "Load Factor는 현재 저장된 데이터 수가 해시 테이블 용량에 비해 어느 정도 차면 크기를 확장할지를 결정하는 기준입니다.
>
> 너무 많이 채우면 충돌 가능성이 높아지고, 너무 일찍 확장하면 메모리 사용량이 증가할 수 있습니다."

**핵심 요약**

**Load Factor는 HashMap을 언제 확장할지 결정하는 기준이다.**

---

<a name="q24"></a>
### Q24. TreeMap과 HashMap 중 범위 검색에는 왜 TreeMap이 유리한가요?

> "TreeMap은 Key를 정렬된 상태로 유지하기 때문에 특정 Key 이상·이하 또는 일정 범위의 데이터를 순서대로 찾는 기능을 효율적으로 제공할 수 있습니다.
>
> HashMap은 Key의 정렬 관계를 유지하지 않습니다."

**핵심 요약**

**범위 검색은 Key 순서를 유지하는 TreeMap이 유리하다.**

---

<a name="q25"></a>
### Q25. 배열과 LinkedList의 메모리 구조는 어떻게 다른가요?

> "배열은 요소를 연속적인 영역에 저장하고, LinkedList는 각 노드가 데이터와 다른 노드를 가리키는 참조를 함께 저장합니다.
>
> 따라서 LinkedList는 추가 참조 공간이 필요하고 데이터가 메모리에 분산될 수 있습니다."

**핵심 요약**

**Array는 연속 저장 / LinkedList는 노드와 참조로 연결**

---

<a name="q26"></a>
### Q26. 자료구조는 어떤 기준으로 선택해야 하나요?

> "어떤 연산을 가장 많이 수행하는지를 기준으로 선택해야 합니다.
>
> 인덱스 조회가 많다면 ArrayList, 빠른 Key 조회가 필요하다면 HashMap, 정렬된 Key가 필요하다면 TreeMap, 중복 제거가 필요하다면 Set처럼 요구사항에 맞게 선택합니다."

**핵심 요약**

**자료구조는 조회·삽입·삭제·정렬·중복 허용 여부 중 어떤 연산이 중요한지를 기준으로 선택한다.**
